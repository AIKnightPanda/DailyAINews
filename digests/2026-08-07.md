### Box CEO Aaron Levie：给 agent 写 prompt 更像写规格说明

本期最值得读的一条。**Aaron Levie（levie on X）** 认为大多数人对 agent 的认知还卡在聊天机器人阶段："给 agent 写 prompt 更接近写一份规格说明，而不是问一个问题——你必须充分界定任务范围，并定义清楚什么叫'完成'。"

他的核心论点是：agent 的真正上限不在于把它当成又一个可以提问的系统，而在于**改造工作流本身**——给 agent 正确的数据、打通组织边界、重新设计人工复核环节。他预测企业内绝大部分 token 消耗最终会来自被"部署"进工作流去执行任务的 agent，而非对话。

另一条则反驳了"agent 会冲击某些软件品类"的流行叙事，借 Atlassian 财报大超预期指出：当 agent 生成 100 倍的代码、处理海量数据、跨系统做决策时，管理这些数据和工作流的平台只会更重要，不会更不重要——治理、安全、合规、护栏恰恰是企业最在意的。

### Claude Blog：用 Foundation Models framework 为 Apple 平台构建智能应用

Anthropic 发布了一个新的 Swift 包，让 Apple 开发者能通过苹果的 Foundation Models framework 直接调用 Claude。设计思路是分工：苹果的端侧模型负责快速本地任务（摘要、信息抽取），当请求需要多步推理、代码生成等更复杂的工作时**交接给 Claude**——Claude 还能联网搜索最新信息、执行代码做数据分析，响应可流式回到同一个视图里。

一个关键的工程收益是：苹果框架通过 `@Generable` 注解返回类型化的 Swift 值，所以开发者抵达 Claude API 调用时拿到的是干净的结构化输入，而不是原始用户文本。

官方举的例子很能说明模式的价值——日记应用可以在端侧生成每日提示，再让 Claude 跨越几个月的条目找出主题脉络；学习应用可以在端侧解释一个术语，当学生追问"这为什么对我们学过的其他东西都很重要"时再交接给 Claude。对用户是一套体验，每一步背后是合适的模型。

支持 iOS 27、iPadOS 27、macOS 27、visionOS 27、watchOS 27，需用 Anthropic API key 登录，该包自行处理流式传输、工具调用和结构化响应。

## 三、播客

### The MAD Podcast：如何构建长任务 AI Agent —— Mitch Troyanovsky, Basis

**核心结论**：长任务 agent 的瓶颈不是模型能力，而是你有没有像设计一家公司的流程那样，为不确定性实体设计出可验证的协作系统。

Mitch Troyanovsky 是 Basis 的联合创始人，这家独角兽公司的 agent 能自主运行数小时甚至数天，端到端完成整份报税表。这类工作没有编码任务那样现成的验证器，所以他被迫想清楚了很多别人还没遇到的问题。

他最反直觉的一个视角是把 agent 设计**还原成组织设计**："人类早就习惯与非确定性系统协作了，只不过那些系统通常是他们的同事，而不是他们的电脑。公司和流程本质上就是在设计一套让非确定性实体协同解决问题的系统。"想明白这点，答案就在会计师事务所现成的做法里：分步验证、独立复核、可确定性核对的检查项（试算平衡表是否配平、Excel 有没有报错），再加上那些"会计一眼就知道不对"但无法确定性验证的东西——后者正好可以做成 judge，既用在 evals 里也用在运行时。

他对评测的标准高得罕见："假设你有 100 个 eval，全过了，看起来不错。但你有信心它能泛化到真实生产环境吗？我们的答案是：不能。"他的类比很锋利——即使一个人 100 次全做对了，如果他是靠翻维基百科做对的，会计师事务所也不会雇他，那么同理也不该雇我们。

这就是 Basis 押注**行为规格（behavior specs）**和过程监督而非只看结果的原因：对错误的过程给出正确答案，仍然是失败。但他也警告 behavior spec 是有维护成本的状态，"你理想情况下应该尽可能少写"——只挑那几条泛化性最强、最关键的，而不是把所有最佳实践都写下来。

最扎心的一句是对 agent 开发者的批评："你会看到有人因为一个代码文件抽象得不好而崩溃，可他们的 context 简直是一坨狗屎。英语比代码更珍贵，因为**英语影响运行时性能，代码不影响**。"
