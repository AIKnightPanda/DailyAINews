### Meta AI 高级总监 Madhu Guru：企业做不好 AI，是因为没有 eval 策略

**Madhu Guru（realmadhuguru on X，Meta AI 高级总监，曾在 Google 主导 Gemini、Veo、Nano Banana）** 的 eval 系列第四篇，是本期最可直接落地的内容。他的核心判断："企业在构建像样的 AI 系统上举步维艰，根源是缺乏 eval 策略。"

他主张一套**阶梯式 eval 策略**——针对自己独特的用例，在成本/真实度光谱上布置多层评测：

- **爬坡 eval（hill-climb）**：推动产品能力边界，需要持续刷新，用来提升质量、扩展功能面
- **回归 eval（regression）**：爬坡的同时，有没有把今天的产品搞坏？
- **冒烟 eval（smoke test）**：安全底线和绝对基础，题目不一定难，但绝不能错——比如产品身份认知
- **上线 eval（launch）**：接近真实流量的在线测试，可控性最低，但最真实

### Anthropic Engineering：关于近期 Claude Code 质量反馈的复盘

这是一篇少见的、把话说得很具体的事故复盘。过去一个月里关于"Claude 回答变差了"的反馈，被追溯到**三个互相独立的变更**，影响了 Claude Code、Claude Agent SDK 和 Claude Cowork——**API 未受影响**。三个问题均已在 v2.1.116 修复。

三个变更分别是：

1. **3 月 4 日**，把 Claude Code 默认推理强度从 high 降到 medium，本意是缓解 high 模式下长到"UI 看起来像卡死"的延迟。官方直接承认"**这是个错误的权衡**"，并在 4 月 7 日回滚——因为用户表示更希望默认走高智能，简单任务再自行降档。影响 Sonnet 4.6 与 Opus 4.6。
2. **3 月 26 日**，为降低恢复会话时的延迟，上线了"清理闲置一小时以上会话中较早思考内容"的改动。一个 bug 导致这个清理在整个会话剩余时间里**每一轮都执行**，而非只做一次，于是 Claude 显得健忘且重复。4 月 10 日修复。同样影响 Sonnet 4.6 与 Opus 4.6。
3. **4 月 16 日**，加入了一条降低冗长度的系统提示词指令，与其他提示词改动叠加后**损害了编码质量**，4 月 20 日回滚。影响 Sonnet 4.6、Opus 4.6 与 Opus 4.7。

最值得琢磨的是他们对"为什么这么难查"的解释：由于每个变更影响的是不同的流量切片、且时间表各不相同，**叠加起来的表象是一种宽泛而不一致的整体退化**。团队 3 月初就开始调查，但初期难以把它和用户反馈的正常波动区分开，内部使用和 evals 一开始都没能复现。作为补偿，4 月 23 日起为所有订阅用户重置了用量限制。

### Anthropic Engineering：扩展 Managed Agents —— 把大脑和手解耦

这篇提出了一个很值得记住的观点：**harness（脚手架）编码的是"Claude 自己做不到什么"的假设，而这些假设会随模型变强而过期**，所以必须被反复质疑。

他们给了一个自己踩过的例子：Claude Sonnet 4.5 会在感知到上下文上限逼近时提前草草收尾（所谓"上下文焦虑"），他们为此在 harness 里加了上下文重置；可当同一套 harness 用在 Claude Opus 4.5 上时，这个行为消失了——**那些重置变成了死重量**。

于是他们构建了 Managed Agents，并把它类比成操作系统当年解决的问题：如何为"尚未被构想出来的程序"设计系统。几十年前操作系统把硬件虚拟化成 **process**、**file** 这类足够通用的抽象，抽象活得比硬件久——`read()` 并不关心自己读的是 1970 年代的磁盘组还是现代 SSD。Managed Agents 照搬了这个套路，把 agent 的组件各自虚拟化：**session**（记录一切发生过的事的追加日志）、**harness**（调用 Claude 并把工具调用路由到相应基础设施的循环）、**sandbox**（Claude 执行代码和改文件的环境），从而让任一实现都能被替换而不惊动其他部分。

文中还有一节叫「别养宠物」，讲的是他们最初把所有组件塞进单个容器的后果：容器成了 pets-vs-cattle 里那只"宠物"——挂了会话就没了，卡住得靠人工救活，而唯一的观察窗口 WebSocket 事件流分不清究竟是 harness 的 bug、事件流丢包还是容器掉线。更糟的是，要排查就得进容器开 shell，而那个容器往往还装着用户数据，**等于实际上失去了调试能力**。

🔗 https://www.anthropic.com/engineering/managed-agents

### Claude Blog：Managed Agents 新增自托管沙箱与 MCP 隧道

上一篇的产品化落地。即日起 Claude Managed Agents 可以在**你自己控制的沙箱**中运行，并连接到你的私有 MCP 服务器——agent 执行工具的沙箱和它触达的服务，都在企业既有的边界内，受你自己的安全与运行时控制。目前自托管沙箱为公开测试，MCP 隧道为研究预览（需申请）。

分工很清晰：**编排、上下文管理和错误恢复的 agent 循环仍在 Anthropic 的基础设施上，工具执行则移到你配置的环境里**。代码执行、敏感文件、依赖包、服务和数据都不出企业边界，网络策略、审计日志和安全工具链沿用现成的；算力也归你控制——资源规格和运行时镜像由你设定，所以长时间构建、图像生成这类重计算任务能拿到需要的 CPU 和内存。

沙箱可以自带，也可以用支持的托管方，各有侧重：**Cloudflare** 用 microVM 和更轻量的 isolate 大规模运行沙箱，出站请求受零信任密钥注入控制，可自定义代理来审计、改道或修改出口流量；**Daytona** 的沙箱是完整可组合的计算机，长时运行且有状态，会话期间可通过 SSH 或带认证的预览 URL 访问，也可以暂停后带完整状态恢复；**Modal** 的沙箱与其函数、存储、网络原语同源，自研容器运行时可在任意镜像上做到亚秒级启动，并扩展到数十万并发；**Vercel** 的沙箱结合 VM 安全、VPC 对等和自带云，启动时间以毫秒计，且**凭据由沙箱防火墙在网络边界注入，从不进入沙箱内部**。

已有落地案例：Amplitude 基于 Managed Agents + Cloudflare 构建内部设计工具 Design Agent；Clay 的 GTM 工程 agent Sculptor 跑在 Managed Agents + Daytona 上；面向机构金融的 Rogo 则用 Managed Agents + Vercel Sandbox 处理专有数据。

### No Priors：从恢复视觉到重新构想大脑 —— Max Hodak

**核心结论**：如果大脑真的只是一台通过少数几根线缆与世界相连的计算机，那么修复感官就不是医学问题，而是工程问题——而工程问题有确定的改进路径，生物学没有。

Max Hodak 是 Science 公司的创始人兼 CEO，此前是 Neuralink 的联合创始人。他们的主打产品 Prima 是一款**视网膜假体**，刚刚在欧洲获得监管批准。

他把它类比成"眼睛的人工耳蜗"：一枚微小芯片被植入视网膜之下，患者佩戴的眼镜带有激光投影仪，把图像投射到植入体上，绕过已死亡的视杆和视锥细胞直接刺激视网膜，从而把视觉信号送回大脑。适应症是感光细胞丧失导致的失明——临床试验做的是黄斑变性，接下来将开展视网膜色素变性、Stargardt 病等研究。

临床试验结果他自己形容为"好得不像真的"：**有患者在填数独和填字游戏，有患者在读书**。"此前从没有人能以这种方式在盲人患者的心灵之眼中恢复出成形的视觉图像。"但他对现状同样直白——视野很小，"**像是透过一根吸管看东西**"，而且只有黑白。下一步是增加灰阶深度，他认为至少能做到红和绿，蓝色更棘手。当前版本面向美欧数十万患者，下一版本正在动物实验、有望明年进入人体，可将范围扩大到数百万人。

他反复回到那个会激怒互联网的论断上——"**如果你想让人生气，就去跟互联网说大脑是一台计算机**"。但他坚持这不是隐喻：大脑通过颅神经和脊神经这少数几根"小线缆"与环境相连，视神经是第二对，负责听觉与平衡的前庭蜗神经是第八对。"我们谈论缸中之脑，可颅骨就是那个缸。"因此在他看来，把视觉、听觉、平衡、运动和体感信号送进送出大脑，**本身就是目的，就是那个核心对象**。

这也解释了他为什么选择器械而非药物："如果我把电极放进初级运动皮层，你大概一小时后就能用电脑了。"相比之下，小分子药物研发可以做十年，临床试验翻开一张牌，答案可能是否定的，然后所有人就散场回家了——而器械这条路"我们很清楚该怎么把这东西做得更好"。

至于长远处，他的世界观相当极端也相当自洽：大脑是唯一一个原则上都无法移植的器官，"心脏、胰腺、肝脏、肺，在我看来都是配角，它们存在是为了让大脑的活动保持有趣、保持运转。"他补了一句听起来像玩笑但显然不是的话——"**如果我最后是被自己的胰腺谋杀的，我会相当失望。**"
