### Meta AI 高级总监 Madhu Guru：别把漂亮的 eval 套件压成一个分数

**Madhu Guru（realmadhuguru on X）** 的 eval 系列第五篇，直指一个几乎所有团队都会犯的错——把复杂的评测结果简化成单一分数，通常是因为某位高层想要一个便于决策的数字。他说 Gemini 早期他们自己就这么干过。

他给这个现象起了个名字：**平均数的暴政（the tyranny of the average）**。理由是 AI 系统的质量根本不是一个单一维度。他举的例子很直观——某个模型从：

- 简单摘要 85% → 89%
- 基础事实问答 80% → 85%
- **复杂财务分析 70% → 63%**

单一分数会掩盖掉一个事实：模型在**你的前沿用例上变差了**。

而常见的补救——加权平均——在他看来更糟："你为一个判断性的决定制造了虚假的、数学化的精确感。"他给的做法是：按第四篇讲的阶梯保留一份带优先级的 eval 清单；找那些愿意看细节、不追求抽象简化的人；把所有关键 eval 结果理解透——在哪儿失败、在哪儿出色——然后判断新系统对用户到底是更好还是更差。

### Anthropic 的 Thariq：内部用得很多的一个 skill —— ELI5

**Thariq（trq212 on X，Claude Code @ Anthropic）** 分享了 Anthropic 内部最近用得很多的一个 skill：`/eli5`，全称是"解释得像我对这个话题一无所知，用一个图大字少的 HTML artifact"。

他给的用法例子说明了它的真实场景不止于教学：

- `/eli5 how does this module work` —— 搞懂一个模块
- `/eli5 why did we make this tradeoff` —— 追溯一个权衡的来由
- `/eli5 what caused this incident` —— 复盘一次事故

他说正在考虑要不要把它做成官方插件，目前可以先从社区市场装：

```
claude plugin marketplace add anthropics/claude-plugins-community
claude plugin install eli5@claude-community
```

### Box CEO Aaron Levie：智能便宜到不用计量之后，机会在扩散

### No Priors：Chess.com 告诉我们的超人能力启示 —— Erik Allebest

**核心结论**：国际象棋是"超人 AI 已经存在三十年"的活体样本，而它给出的答案是——人类技艺不但没有贬值，反而比历史上任何时候都更繁荣。

Erik Allebest 是 Chess.com 的 CEO。2005 年他从破产拍卖里以 **55 美元**买下 chess.com 这个域名，当时几乎所有投资人都告诉他这是个不可投资的小众爱好项目。二十年后的今天：约 **1000 万日活、四五千万月活、超过 2.5 亿注册会员**，今年收入将略超 **2 亿美元**，团队约 650 人，目标是让十亿人下棋。他自己形容这些数字"说出来都觉得离谱"。而且这门生意**从未依靠融资输血来增长**——历次交易都是老股东之间的股份转让，没有注资。

最值得 AI 从业者听的是他对"超人机器"的态度。计算机在国际象棋上碾压人类已经三十年，当年很多人认为这是对这项运动的生存威胁、会终结这个游戏。结果恰恰相反。他的结论说得毫不含糊：

> "非常清楚的是，即使机器能超越他们，人们依然想获得人类的技能，而且他们想看。即使机器能做得好得多，他们依然欣赏卓越的人类技艺。……认为在超人 AI 的世界里人类技能不再相关、而且这仅仅是技术本身的产物——这种想法是无稽之谈。"

他对作弊的讨论也几乎可以整段搬到今天的 AI 语境里——毕竟这正是"机器能产出超人结果，并冒充人类表现"的最早战场。他承认这件事让人沮丧，但也提醒：**象棋对抗作弊的历史远早于 AI**，而且"我们同样拥有对抗作弊的技术"。他们在反作弊上投入了大量时间、金钱和资源，靠的是更多数据、更多统计模型和机器学习模型——至于具体手段，他明确表示不打算细说，免得给人提供思路。

关于如何变强，他给的答案"既幸运又不幸地"简单：没有捷径，就是小模块的重复——做战术题、复盘自己的错误、针对性训练。"这和你训练神经网络是一样的：你喂给它一堆数据。当然它可以并行训练……我们的大脑不太是那样运作的，但我们必须把重复次数放进去。"他认为社交媒体带来的即时性让很多人忘了，**练习是无法走捷径的**。

至于 AI 在公司内部的用法，他描述了一种"共生"：自动化让支持团队更快给出答案，而人类同事负责创造这些自动化并处理真正需要人对人的部分；数据分析师用 LLM 去问和答更有意思的问题；产品开发上则推进 agentic development，目标是"**缩短从发现机会或问题、到把代码推给用户之间的时间**"——因为层层交接的传统流程会把这个周期拖得非常长。
