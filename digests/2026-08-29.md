### Thibault Sottiaux：OpenAI 终止向 Cursor 提供模型，11 月 12 日生效
OpenAI Codex & ChatGPT 负责人 Thibault Sottiaux（thsottiaux on X）宣布，OpenAI 决定不再继续通过 Cursor 提供模型访问，双方合作终止：「We unfortunately have decided that we cannot continue providing access to our models through Cursor and are ending our partnership. It boils down to trust」。这一决定将于 11 月 12 日生效，给用户留出过渡时间。

对于原本通过 Cursor 使用 GPT 模型的开发者，Sottiaux 给出了两条后续可用的路径：一是继续用自己的 OpenAI API key，二是通过 OpenAI 自家的 IDE 插件访问。他强调 OpenAI 仍会持续投入开源生态、并与更广泛的工具和 harness 合作（包括开源和闭源的）。详情写在官方博客里 （[SpaceX 收购 Cursor 后 OpenAI 的决定](https://openai.com/index/our-decision-on-cursor-following-its-acquisition-by-spacex)）。

同一时间线上，Sottiaux 还提到「Looking at the dashboard we might hit a new milestone to celebrate tomorrow」，暗示 Codex 使用量即将迎来新的里程碑。

值得一提的是，Anthropic 的 Claude Code 团队成员 Thariq（trq212 on X）在同一时期公开表态「Long-time admirer of the Cursor team, few have done more to bring AI coding to the world. Excited to continue to partner with them」，与 OpenAI 的决定形成对照 —— Anthropic 明确表示将继续与 Cursor 合作。

### Peter Yang：Claude Cowork、ChatGPT Work 都是过渡形态，Grok Bot 才是终局
AI 教程作者 Peter Yang（petergyang on X）抛出一个反共识判断：「My hot take is that Claude Cowork and ChatGPT Work are partial solutions and that Grok Bot is the right end state for a capable AI agent product for non-technical people.」

### Madhu Guru：AI 产品的打法半衰期只有约 3 个月，团队要为「持续发明」而非「挤压存量打法」而建
Meta AI 高级总监、曾主导 Gemini/Veo/Nano Banana 的 Madhu Guru（realmadhuguru on X）提出一个判断：「AI product building has a ~3-month playbook half-life.」

传统产品团队的组织方式，是找到一套打法之后再靠它「挤」出未来 5 年的收益；但在 AI 实验室里，团队会主动、有意识地每隔几个月就抛弃现有打法，因为边际收益已经开始递减。他给建造者的具体建议是聚焦两条元原则：一是持续搞清楚市场现在要什么、三个月后可能要什么；二是以极高的执行紧迫感去落地。「Legacy teams are optimized for playbook milking. AI teams need to be optimized for inventing.」

### Guillermo Rauch：Web 正在向两个极端演化，agent 是「中间态」的新浏览器
Vercel CEO Guillermo Rauch（rauchg on X）提出他对 Web 演化方向的判断：内容和体验正在分裂成两个极端。一端是「ultra-fancy human experiences」——为了愉悦感、探索性、品牌和娱乐服务的超精致人类体验，由 three.js、typegpu 这类技术驱动；另一端是「agent-centric content, data and APIs」——纯粹、无损的机器可读信号，markdown 和 MCP 的兴起只是这个趋势的冰山一角。

他认为「中间态」（那些为人类设计但信息密度不高的功能性内容）会逐渐被 agent 现场生成的 UI 取代：「When you need utilitarian content or data, it'll be generated just-in-time for you. Think of the agent as the new browser in this model.」

Rauch 同时指出 MCP 的采用正在爆发式增长，以 `mcp-handler` 这个 npm 包的下载量为例。他还提到 Vercel 新推出的 agent 项目 eve，主打「你真正拥有整个智能栈」——runtime、模型选择、skills、工具、连接性、沙箱都在一个 Git 仓库里，而不是被封装在黑盒产品里。

### Anthropic：复盘四月 Claude Code 质量问题，三个独立改动叠加导致体验下滑
Anthropic 工程团队发布复盘文章，正面回应「Claude 响应质量变差」的用户反馈。调查发现问题并非模型或推理层本身的退化（API 未受影响），而是三个独立改动叠加造成的：

一是 3 月 4 日，Claude Code 把默认推理强度从 high 降到 medium，目的是缓解 high 模式下偶发的超长延迟（UI 会显得卡死）。内部评测显示 medium 强度智能水平略低但延迟显著更好，团队因此推了这个改动。但用户反馈觉得「变笨了」，4 月 7 日团队撤回，现在 Opus 4.7 默认 xhigh，其余模型默认 high。

二是 3 月 26 日上线的一项缓存优化：为了给闲置超过一小时的会话降低恢复成本，本应只清理一次旧的 thinking 内容，结果一个 bug 导致每个后续回合都在重复清理，让 Claude 显得健忘、爱重复。4 月 10 日修复。

三是 4 月 16 日为降低啰嗦程度加的一条系统提示词，叠加其他提示词改动后损害了编码质量，4 月 20 日撤回。

三个改动分别影响不同的流量切片、在不同时间生效，叠加后呈现出「广泛而不一致的质量下滑」的表象，也是团队早期难以定位问题的原因之一。Anthropic 原话反思：「This isn't the experience users should expect from Claude Code.」作为补偿，4 月 23 日起为所有订阅用户重置了用量限额。

🔗 https://www.anthropic.com/engineering/april-23-postmortem

### Anthropic：发布 Managed Agents，把「大脑」和「手」解耦
Anthropic 工程团队发布 Managed Agents——Claude Platform 上的托管服务，用一小组稳定接口运行长周期 agent。核心思路来自操作系统设计的老问题：如何为「尚未被想到的程序」设计抽象。就像 `process`、`file` 这类抽象让操作系统在硬件变化时保持稳定一样，Managed Agents 把 agent 拆成三个可独立替换的组件：**session**（记录一切事件的仅追加日志）、**harness**（调用 Claude 并把工具调用路由到相应基础设施的循环）、**sandbox**（Claude 执行代码和编辑文件的运行环境）。

团队早期把这三者塞进同一个容器，结果撞上了经典的「宠物 vs 牲畜」问题：容器变成了不能丢失的「宠物」——容器一挂会话就没了，容器卡住就得靠人工「抢救」。调试尤其痛苦：唯一的观测窗口是 WebSocket 事件流，harness 的 bug、事件流丢包、容器离线在外部看起来完全一样，工程师只能进容器开 shell 排查，但容器里往往还装着用户数据，这条路基本走不通。另一个问题是 harness 默认假设 Claude 处理的一切都在同一个容器里，当客户希望把 Claude 接入自己的 VPC 时，只能选择打通网络或者把 harness 部署到客户环境——写死在 harness 里的假设成了扩展的障碍。

解决方案是让 harness 离开容器：它把容器当成普通工具调用，`execute(name, input) → string`，容器彻底变成「牲畜」——挂了就是一次工具调用报错，Claude 可以选择用 `provision({resources})` 重新拉起一个标准容器。因为 session 日志独立存放在容器和 harness 之外，harness 本身也变成了可替换的：一个 harness 崩溃后，新的 harness 可以用 `wake(sessionId)` 唤醒、用 `getSession(id)` 取回事件日志、从最后一个事件继续。

## 三、播客

**核心结论**：在 AI 时代，企业数据本身，而非模型或算力，才是最持久、最难复制的资产——但 AI agent 的普及也带来了前所未有的安全威胁，企业急需一整套新的基础设施去发现、分类、保护和激活散落各处的数据。

No Priors 播客本期请来了 EON 的两位联合创始人 Ofir Ehrlich 和 Gonen Stein。Ofir 此前创立过云灾备公司 CloudEndure，后被 AWS 收购，这次他和 Gonen 一起做的 EON 专注云备份和灾难恢复。他们的判断建立在一线的观察上：「Models, compute, everything is relatively ephemeral, almost zero switching costs. But if you're a company...the most valuable thing that you have is actually your data.」

一个很能说明问题的例子是：Google 花了 1000 万美元买下破产的 Spirit Airlines 的数据用于训练模型，Mercor 等公司也在竞标类似的破产数据集——这足以说明数据在 AI 训练里的真实市场价值。与此同时，企业的 CEO 和董事会正在用力施压，要求把「沉睡」多年的数据激活起来:「we have a lot of data in the organization. We now realize data is new oil. We can actually activate it with the new tools that we have today.」但现实很骨感——这些数据往往散落在跑了二十年的各种老系统里，大多没分类、混杂着 PII 和财务等敏感信息，甚至没人能完全说清系统架构，公司里常有那种「没人敢关」的神秘服务器。

更棘手的是安全层面的新威胁。AI agent 拥有合法的系统访问权限，却能以远超人类的速度执行破坏性操作，比如误删数据库表；而现有的检测和防护逻辑,基本还是照搬针对人类威胁设计的那一套，没跟上。两人还提到一个正在失控的现象：不少非技术人员用 Lovable 这类工具自己搭 agent，缺乏基本的安全意识，公司数据因此有暴露和被误用的风险——「Agents activating other agents would activate other agents and trying to keep track of the non human identity...becomes almost an impossible task.」

企业内部还存在一个结构性矛盾：董事会和 CEO 要求立刻用起 AI、不许拖延；IT 主管和数据团队却对 agent 可能造成的数据泄露和 IP 外流深感恐惧，而数据团队与业务部门的激励机制本来就不一致，很难简单地把数据抽取出来对齐使用。两人认为，旧的 ETL 类工具（Fivetran、DBT、Monte Carlo）过于专用化，跟不上 agent 时代数据增长的速度和规模，这也是 Databricks 这类公司开始自建 agent 和数据库、想要重新掌控数据生成和使用方式的原因。他们还观察到企业采纳 AI 出现了新模式：带着硅谷工具集空降进传统企业做转型的 forward deployed engineer 正在成为主流打法，PLG 在 agent 工具赛道里也在爆发式增长；不少大型企业选择直接收购初创公司而非自建，以更快获得 AI 能力。但多数企业仍处于这场旅程的早期——理解数据的重要性,却仍然害怕真正的变革。
