### OpenAI 终止与 Cursor 的合作，11 月 12 日生效；Anthropic、Replit 当场接盘

OpenAI 的 Codex 与 ChatGPT 负责人 Thibault Sottiaux（thsottiaux on X）宣布，OpenAI 决定不再通过 Cursor 提供自家模型，合作在 11 月 12 日终止。他把原因说得很直白：

「归根结底是信任问题。我们把生效时间定在 11 月 12 日，好让你们有时间做规划。」（原文："It boils down to trust and we've asked that this takes effect on November 12 to give you some time to plan."）

他同时给了现有用户两条退路：继续用自己的 OpenAI API key，以及继续通过 OpenAI 面向 Cursor 的 IDE 扩展访问模型。他强调 OpenAI 仍会支持尽可能广的工具与 harness 生态，"包括很多开源的，也包括很多闭源的"，并继续投入自家的开源项目。完整说明见 OpenAI 的公告 （[SpaceX 收购 Cursor 后 OpenAI 的决定](https://openai.com/index/our-decision-on-cursor-following-its-acquisition-by-spacex)） —— 该文把这个决定与 Cursor 被 SpaceX 收购一事直接关联。

几乎同一时间，两位竞品负责人下场：

- Anthropic 的 Claude Code 团队成员 Thariq（trq212 on X）表态站在 Cursor 一边 ——「长期以来我都很欣赏 Cursor 团队，把 AI coding 推向世界这件事上，没几个人做得比他们多。」（原文："Long-time admirer of the Cursor team, few have done more to bring AI coding to the world."）并称会继续与他们合作。

### Vercel CEO Guillermo Rauch：网页正在裂成两个极端，agent 是新的浏览器

Guillermo Rauch（rauchg on X）判断 web 会往两头走，中间地带会被吃掉：

- 一端是**极度精致的人类体验**，为了愉悦、探索、品牌和娱乐服务 —— threejs、typegpu 这类东西在支撑它。
- 另一端是**面向 agent 的内容、数据和 API**，纯粹、无损的机器信号 —— markdown 和 MCP 的兴起只是冰山一角。

「夹在中间的那部分，很可能会被 agent 即时生成的 UI 吞掉。当你需要功能性的内容或数据时，它会为你即时生成。在这个模型里，把 agent 当成新的浏览器。」（原文："The 'in between' is likely to be subsumed by agents producing just-in-time UI. When you need utilitarian content or data, it'll be generated just-in-time for you. Think of the agent as the new browser in this model."）

他用数据佐证了 MCP 这一侧的动能：不只是 Vercel MCP，用来实现 MCP server 的 `mcp-handler` 这个 npm 包，下载量也在爆发式增长。

另外他推了 eve —— 他的问题是，市面上"轻松创建 agent"的路子很多，但有几个能给你一个 Git repo、让你真正**拥有**整套智能栈：runtime、模型选择、skills、tools、连接性、sandbox。

### Box CEO Aaron Levie：AI 圈的"坚定信念"半衰期最多六个月

### Meta AI 高级总监 Madhu Guru：AI 产品的 playbook 只有三个月保质期

Madhu Guru（realmadhuguru on X，现任 Meta AI 高级总监，此前在 Google 主导 Gemini、Veo 和 Nano Banana）给出一个更具体的量化版本：「做 AI 产品，playbook 的半衰期大约三个月。」（原文："AI product building has a ~3-month playbook half-life."）

他的对照很尖锐：传统产品团队的构造是"发现一套打法，然后靠它吃五年"；而在大模型实验室里，「我们每隔几个月就有意识地把 playbook 扔掉，因为我们开始看到收益递减。」（原文："in the AI labs, we consciously throw away playbooks every few months cos we start seeing diminishing returns."）

他给 AI builder 的建议是别去定义打法本身，而是定义两条元原则：

1. 怎样持续搞清楚市场今天想要什么、三个月后可能想要什么
2. 怎样以极端的紧迫感去执行

具体内容因领域和产品形态而异，但团队必须按这个节奏学习和调整。他的结论一句话：老牌团队为"榨取打法"而优化，AI 团队要为"发明"而优化。

### Anthropic Engineering：Claude Code"变笨"的三次事故复盘，并为所有订阅用户重置用量额度

Anthropic 承认过去一个月用户报告的 Claude Code 质量下滑属实，追查到三处互相独立的改动，影响 Claude Code、Claude Agent SDK 和 Claude Cowork，**API 未受影响**。三个问题已在 4 月 20 日（v2.1.116）全部修复。

三处改动分别是：

- **3 月 4 日**，把 Claude Code 默认 reasoning effort 从 high 降到 medium，本意是缓解 high 模式下偶发的超长延迟（长到界面看着像卡死了）。这是个错误的取舍，4 月 7 日回滚。影响 Sonnet 4.6 和 Opus 4.6。现在 Opus 4.7 默认 xhigh，其余模型默认 high。
- **3 月 26 日**，为降低恢复空闲会话时的延迟，清理闲置超过一小时的会话中的旧 thinking。一个 bug 导致这个清理在此后**每一轮**都执行，而不是只做一次，于是 Claude 显得健忘又啰嗦。4 月 10 日修复。影响 Sonnet 4.6 和 Opus 4.6。
- **4 月 16 日**，加了一条要求减少冗长的 system prompt 指令，叠加其他 prompt 改动后损害了编码质量，4 月 20 日回滚。影响 Sonnet 4.6、Opus 4.6 和 Opus 4.7。

因为三处改动各自命中不同的流量切片、按不同时间表推进，叠加起来就呈现为"大面积、不稳定的退化"。Anthropic 说 3 月初就开始调查，但早期难以从正常的用户反馈波动中分辨出来，内部使用和 evals 一开始也复现不出问题。

「我们从不故意降低模型能力，而且我们当即确认了 API 和推理层未受影响。」（原文："We never intentionally degrade our models, and we were able to immediately confirm that our API and inference layer were unaffected."）文章还顺带指向了他们讲缓存策略的那篇 [prompt caching is everything](https://claude.com/blog/lessons-from-building-claude-code-prompt-caching-is-everything)。

实际补偿：自 4 月 23 日起，为所有订阅用户重置用量额度。

🔗 https://www.anthropic.com/engineering/april-23-postmortem

### Anthropic Engineering：Managed Agents 把"大脑"和"手"拆开

Anthropic 在 Claude Platform 上推出 **Managed Agents** —— 一个托管服务，替你运行长周期 agent（[官方文档](https://platform.claude.com/docs/en/managed-agents/overview)）。

出发点是个反直觉的观察：「harness 编码的是关于 Claude 自己做不到什么的假设。而这些假设需要被频繁质疑，因为随着模型变强，它们会过期。」（原文："harnesses encode assumptions about what Claude can't do on its own. However, those assumptions need to be frequently questioned because they can go stale as models improve."）他们举了自己的例子：Sonnet 4.5 会在感到上下文快满时提前草草收尾（所谓"context anxiety"），于是他们在 [harness 里加了 context reset](https://www.anthropic.com/engineering/harness-design-long-running-apps)；换到 Opus 4.5，这个行为消失了，那些 reset 变成了纯粹的负担。

所以他们把 agent 虚拟化成三个部件：**session**（记录一切的 append-only 日志）、**harness**（调用 Claude、把工具调用路由到基础设施的循环）、**sandbox**（Claude 跑代码改文件的执行环境）。三者可以各自替换、各自失败。

最初他们把三者塞进同一个容器，结果养出了一只"宠物"（pets vs cattle 里的那个 pet）：容器一挂，会话就没了；容器卡住，只能进去人肉救。而唯一的观察窗口是 WebSocket 事件流，harness 的 bug、事件流丢包、容器掉线看起来一模一样；要查只能进容器开 shell，可容器里往往还装着用户数据 —— 等于没法调试。另一个麻烦是 harness 假定 Claude 要处理的东西就在自己这个容器里，客户想把 Claude 接到自家 VPC 时，就只能对等互联或者把 harness 搬进自己的环境。

拆开之后：harness 搬出容器，像调用任何工具一样调用它 —— `execute(name, input) → string`；容器成了牛，死了就报一个工具调用错误交回给 Claude，重试时用 `provision({resources})` 起个新的。harness 自己也成了牛：因为 session 日志在它外面，崩了就 `wake(sessionId)`、`getSession(id)` 拿回事件流、从最后一个事件继续，循环过程中用 `emitEvent(id, event)` 持久记录。

### No Priors：和 Eon 联合创始人 Ofir Ehrlich、Gonen Stein 聊被遗忘的数据基础设施

**核心结论**：在 AI 时代，企业最关键的资产是自己的数据 —— 它比模型和算力更有价值，因为后两者几乎没有切换成本。

讲这个的是 Eon（云备份与灾难恢复服务）的两位联合创始人 Ofir Ehrlich 和 Gonen Stein。Ofir 此前创办 CloudEndure 并卖给了 AWS，所以他谈的是从企业数据底层看到的实况，不是外部观察。

Ofir 的判断很干脆：「模型、算力，这些东西都相对短命，切换成本几乎为零。但如果你是一家公司……你手上最值钱的东西其实是你的数据。」（原文："Models, compute, everything is relatively ephemeral, almost zero switching costs. But if you're a company...the most valuable thing that you have is actually your data."）

数据值钱到什么程度有个具体价码：Google 花 1000 万美元买下 Spirit Airlines 破产后的数据用于训练模型，Mercor 等公司也在竞标破产数据集。

但企业内部是另一幅光景。董事会和 CEO 在压力下不断喊"数据是新石油，现在有工具能激活它了"，现实却是这些数据散落在二十年积累的各种系统里，大多没分过类，混着 PII 和财务数据，没有人完整理解架构 —— 包括那些没人敢关掉的神秘服务器。数据团队和业务部门的激励也不一致，不是把数据抽出来那么简单。

安全上出现的是全新的威胁模型：AI agent 持有合法的系统访问权限，却能以人类做不到的速度执行破坏性操作（比如删掉数据库表），而现有的检测和防护逻辑还是按人类威胁设计的。更麻烦的是身份追踪 ——「agent 激活其他 agent，那些 agent 再激活别的 agent，想追踪这些非人类身份……几乎是不可能完成的任务。」（原文："Agents activating other agents would activate other agents and trying to keep track of the non human identity...becomes almost an impossible task."）与此同时，非技术人员正用 Lovable 这类工具搭 agent，完全没有安全意识。

他们还观察到企业采纳 AI 的路径在变：forward deployed engineer（工程师带着硅谷那套工具直接进驻传统企业做改造）成了主流打法；agent 工具里 PLG 在爆发；大企业越来越倾向于直接收购初创公司而不是自建，来快速拿到 AI 能力。至于旧的数据栈，Fivetran、DBT、Monte Carlo 这类 ETL 工具在他们看来太专门化了，跟不上失控的数据增长速度 —— 尤其是 agent 自己生产的那部分数据；Databricks 这样的公司则在自建 agent 和数据库，以掌控数据被生产和使用的方式。
