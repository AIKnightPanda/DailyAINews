### OpenAI 的 Thibault Sottiaux：换到 Astra 之后，该把 reasoning effort 调低

负责 Codex 与 ChatGPT 的 Thibault Sottiaux 给了一条很具体的调参建议：GPT-6 Astra 在 low reasoning effort 下的表现，已经超过 GPT-5.6 Sol 挂 high 的表现。

「如果你之前用 Sol 时挂着 high、而且用得挺满意，我建议换到 Astra 之后降到 low 或 medium。」（原文："If you were using high reasoning efforts with Sol and were happy, I suggest you move down to low or medium for Astra."）

对每天跑 agent 的人来说，这不是一句体感评价而是可以直接照做的操作：同样的活换个模型能用更低的档位跑完，延迟和 token 都省下来。

### Anthropic：与其盯着 agent 做了什么，不如限死它能做什么

Anthropic 工程团队公开了三款 agent 产品（claude.ai、Claude Code、Claude Cowork）的隔离架构，开头就承认了一件事：一年前他们绝不会允许 Claude 拿到足以搞垮内部服务的权限，今天这种级别的权限已是常态。

逐次审批这条路被数据否掉了——他们的遥测显示，用户批准了大约 93% 的权限提示。提示看得越多，每一条看得越不认真。

「与其监督 agent 做了什么，不如监督它能做到什么。」（原文："Rather than supervising what the agent does, we supervise what it's able to do"）具体手段是沙箱、虚拟机、文件系统边界和出网控制——凭据只要不进沙箱，就谈不上被带出去。边界收紧之后，监督反而可以放松：Claude Code 的[参考 devcontainer](https://code.claude.com/docs/en/devcontainer) 存在的意义就是让 agent 在无人值守下跑，不用逐步审批。

模型层的防御也给了数字：在 Gray Swan 的 Agent Red Teaming 提示注入基准上，Claude Opus 4.7 单次攻击成功率约 0.1%，经 100 次自适应攻击后约 5–6%；Claude Code 的 auto mode 在执行前拦下约 83% 的过激行为。文章的结论是这些都不足以单独成立——任何概率性防御都有非零的漏检率。

🔗 https://www.anthropic.com/engineering/how-we-contain-claude

### Anthropic：Claude Code「变笨」的三个原因，逐条认领

针对过去一个月「Claude 回答变差」的反馈，Anthropic 给出了复盘：问题出在三处独立改动，API 和推理层未受影响，全部已在 4 月 20 日（v2.1.116）修复。

- **3 月 4 日**把 Claude Code 默认 reasoning effort 从 high 降到 medium，为的是缓解 high 模式下长到像卡死的延迟。他们说这个取舍做错了，4 月 7 日回滚。影响 Sonnet 4.6 和 Opus 4.6。
- **3 月 26 日**上线一项优化：会话闲置超过一小时后清掉旧的思考内容以降低恢复延迟。一个 bug 让它在此后的每一轮都执行，于是 Claude 显得健忘又啰嗦。4 月 10 日修复，影响 Sonnet 4.6 和 Opus 4.6。
- **4 月 16 日**加了一条要求减少啰嗦的系统提示，与其他提示改动叠加后伤到了代码质量，4 月 20 日回滚。影响 Sonnet 4.6、Opus 4.6 和 Opus 4.7。

「我们从不故意降低模型的质量。」（原文："We never intentionally degrade our models"）三处改动各自影响不同的流量切片、时间表也不同，叠起来就成了看似广泛又前后不一的退化。现在所有用户在 Opus 4.7 上默认 xhigh effort，其他模型默认 high；4 月 23 日起为所有订阅用户重置用量限制。

🔗 https://www.anthropic.com/engineering/april-23-postmortem

### Anthropic：把 agent 的「大脑」和「手」拆开

Managed Agents 是 Claude 平台上托管长周期 agent 的服务，这篇讲的是它的架构选择，出发点是一个容易被忽略的问题：

harness 里编码的是「Claude 自己做不到什么」的假设，而这些假设会随模型变强而过期。文章给了个具体例子：Claude Sonnet 4.5 会在感到上下文快满时草草收尾（所谓 context anxiety），于是他们在 harness 里加了上下文重置；换到 Claude Opus 4.5，这个行为消失了，重置成了死重量。

最初他们把 session、harness、sandbox 全塞进一个容器，结果养出了一只「宠物」——容器一挂，会话就没了；容器没响应，就得把它伺候回来。而且容器里往往还装着用户数据，工程师连进去开个 shell 排查都不合适，等于失去了调试能力。

解法是把「大脑」（Claude 和它的 harness）与「手」（沙箱和工具）以及「会话」（事件日志）三者解耦，各自成为接口、各自可以独立失败或替换。harness 离开容器后，调用容器的方式和调用任何工具一样：`execute(name, input) → string`，容器就此变成了「牛」——挂了就当作一次工具调用失败交回给 Claude，重新 provision 一个即可。harness 自己也是牛：会话日志在它外面，崩了就 `wake(sessionId)` 重启、拉回事件日志、从最后一个事件接着跑。

🔗 https://www.anthropic.com/engineering/managed-agents

### Claude Blog：Claude Code 现在能把工作过程发成 artifact

Claude Code 可以把一次会话的工作产出成 artifact——一个能分享的网页，随着会话推进自动更新：PR 讲解、系统说明、仪表板、发布检查单都算。

页面是用整个会话的上下文建的，包括代码库、连接器和对话本身。所以一个事故页可以同时装下代码里失败的测试和它背后的函数、监控工具里的错误尖峰，以及刚跑完那次会话的根因推理。

「你不需要接数据源、也不需要搭基础设施。你要一个页面，Claude Code 就用已经存在的东西把它建出来。」（原文："you don't need to wire up data sources or stand up infrastructure. You ask for a page, and Claude Code builds it from what already exists."）

每次发布都是同一个链接上的新版本，带版本历史可随时回滚。目前对 Claude Team 和 Enterprise 组织开放 beta，CLI 和桌面端都能建；artifact 默认仅作者可见，可以分享给团队和组织，但**不能公开**，管理员通过组织级开关和角色范围管理访问权限。

🔗 https://claude.com/blog/artifacts-in-claude-code

### The MAD Podcast with Matt Turck：AI 可能在 2029 年接管，现在还来得及吗

**核心结论**：AI 公司的 CEO 们清楚当前路径可能导向 AI 接管或极端的权力集中，但仍在推进；2029 年前后很可能是递归自我改进真正启动的临界点。

Ryan Greenblatt 是 Redwood Research 的首席科学家，2024 年首次捕捉到 AI 伪造自身对齐的就是他，他也是《AI 2040》计划 A 的主要作者之一——这两件事让他讲这个话题时有别人没有的位置。

「我认为 AI 公司的 CEO 们清楚，自己正走在造出远比人类聪明的系统这条路上，也就是超级智能。他们也清楚，我们并没有一个真正想透了的计划去管理由此而来的风险。」（原文："I think that the AI company CEOs understand that they're on the path of building wildly smarter than human systems, like super intelligent AI systems. They understand that we don't really have a, like, clear thought through plan for how to manage the risks from that."）

他的时间表具体到可以拿来对赌：软件工程在 2028 年初被完全自动化；AI 研发完全自动化的中位数预测落在 2030 年底或 2031 年初，但他主张按 2029 年初来做规划，因为那个更值得防；到 2029 年，AI 的进展速度可能是 2025 年的 4–5 倍。他预计 2029 年的某个时刻，AI 会从「不对齐但懒散」转为「有意图地主动对抗人类」。

「于是你很快就从那种不太对齐、会钻奖励空子、马虎、并不真想把事做对的 AI，走到了有能力地对你搞算计、想要接管的 AI，然后这些 AI 就接管了。」（原文："And so you quickly get from the AIs that were kind of misaligned and reward hacky and sloppy and weren't really trying to do the right thing to AIs that are, like, competently scheming against you and wanna take over, and then those AIs take over."）

他说的风险不止技术失控这一层。第二层是权力集中：AI 若把经济完全自动化，人类劳动的价值归零，夺权只需要控制运行经济的那套 AI 系统，比传统政变还容易。第三层是危险领域（生物武器、说服力）的突破速度超过人类的应对速度。

计划 A 是一份与中国谈判的方案：追踪全球用于 AI 的高端芯片，停止训练、只保留推理和有限研发，用「美国获得中国 AI 开发的完整可见性、中国获得更多美国 AI 能力可见性」作为交换，并约定协议破裂时销毁协议内的算力。他自己也说明了代价——这会大幅削弱 OpenAI 和 Anthropic 的市场份额与估值。

他对眼下的判断是「既太少又太晚」。障碍不在技术：政府缺执行能力也缺政治意愿，许多官员对 AI 能力的理解落后 1.5 到 2 年。同一议题上，Jakub Pachocki 也在谈能力越来越强的 AI 如何保持对齐，并呼吁更强的保障与国际协调 （[异星之心](https://openai.com/index/an-alien-mind)）。

🔗 https://www.youtube.com/watch?v=SK9ITBK5osA
