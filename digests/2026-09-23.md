### Anthropic Cat Wu：Opus 5.5 已成为 Claude Code 和 Claude App（含 Cowork）默认模型

Cat Wu，Anthropic Claude Code 与 Cowork 团队成员，宣布 Claude Opus 5.5 已成为 Claude Code 和 Claude App（含 Cowork）的默认模型，覆盖 Pro、Max 和 Team 全部套餐。她说自己这几周一直把 Opus 5.5 当日常主力模型在用，尤其喜欢它清晰的沟通风格和“能写出她的语气”的能力。各产品线默认切到 medium 强度，在智力上与 Fable 5.1 相当，但更快；换算下来，同样用量下 Opus 5.5 的速率限制会比 Opus 5 多撑 25%。她的原话是：“We're defaulting to effort medium across products, which is comparable to Fable 5.1 on intelligence but faster.”（我们把各产品线默认设为 medium 强度，这在智力上与 Fable 5.1 相当，但速度更快。）

### Anthropic Boris Cherny：用 Opus 5.5 做形式化验证，揪出 Claude Agent SDK 里人工很难发现的并发 bug

Boris Cherny，Anthropic Claude Code 团队成员，用 Opus 5.5 对 Claude Agent SDK 做形式化验证：几个简短的 prompt，配合 Lean 定理证明语言，就产出了 16 个修复各类 bug 和竞态条件的 PR。他说自己平时也会把 Lean 和 TLA+ 结合起来用，专门排查数据流、并发和状态管理方面的问题——尽管他本人并不精通这两门语言，但 Claude 用得很好。他的原话是：“I used Opus 5.5 to formally verify the Claude Agent SDK using Lean. A couple short prompts = 16 PRs fixing various bugs and race conditions.”（我用 Opus 5.5 通过 Lean 对 Claude Agent SDK 做了形式化验证。几个简短的 prompt 就产出了 16 个修复各种 bug 和竞态条件的 PR。）他由此发问：形式化验证会不会是编程（至少是找 bug）的未来。

另一条推文里他分享了一次对比测试：让 Opus 5.5 和 Fable 5.1 各自把 HAProxy 从 C 移植到 Rust，两者都通过了 HAProxy 几乎全部的测试，但 Opus 5.5 用 9.5 小时完成，比 Fable 5.1 的 12 小时更快，成本还低 51%。他说：“Opus 5.5 is a really good model. It's been my daily driver the last few weeks.”（Opus 5.5 是个很好的模型，过去几周一直是我的日常主力。）

### Box CEO Aaron Levie：模型降价是 agent 领域的 Jevons 悖论，Opus 5.5 在企业任务上实测省 6–8 成 token

Aaron Levie，Box CEO，把当天 Opus 5.5 和 GPT-6 Sol/Luna 双双降价的消息，解读成 agent 领域的 Jevons 悖论：同样的任务成本骤降，能部署 agent 去做的事反而会大幅增加，进而让 AI 在经济中的渗透更广——处理全部数据、扫描代码安全问题、通读全部日志做决策、在工作流里跑 agent 群组，都会因为 token 变便宜而被打开。他的原话是：“This is Jevons paradox applied to agents.”（这就是 Jevons 悖论套用到 agent 身上。）

他随后放出了 Box 用 Opus 5.5 在多个企业知识工作任务上的实测数据：相比 Opus 5，整体 token 用量少 63%，啰嗦程度降 42%，速度快 30%，模型本身还更便宜。具体案例包括：金融尽调场景（准确率 +39%）里，Opus 5.5 用一半的字数、少 82% 的 token 拿到满分；云成本分析场景（准确率 +65%）里，它选对了留存率计算的基准口径，全程保持单位换算一致，用时减半、token 少 70%；客户账户分析场景（准确率 +17%）里，合同没写明高级/初级配比，它从 18 人的花名册里自己推导出规则；临床诊断数据分析场景（准确率 +15%）里，它发现两组标准差相差超过 100 倍、重新按正确方法计算，最终结论是“旱季差异并不成立”。他说：“Overall, we saw frontier capability levels, with major performance improvements over Opus 5.”（总的来说，我们看到了前沿水准的能力，相比 Opus 5 有重大性能提升。）

### Anthropic Alex Albert：一个 prompt，用 Blender 从档案资料还原出 1906 年地震前的旧金山 Market Street

Alex Albert，Anthropic Research 团队成员，用 Opus 5.5 在 Claude Tag 里跑了一个相当硬核的 prompt：还原 1906 年 4 月 17 日、旧金山大地震前一天下午的 Market Street 街景——范围从 Ferry Building 一直到第五街，包含 Palace Hotel、Call Building、Chronicle Building、Lotta's Fountain 和 Emporium。他要求模型先建源文件：综合 1899–1905 年的 Sanborn 火险地图（建筑轮廓、高度、材质、住户）、Miles Brothers 拍摄的纪录片《A Trip Down Market Street》（1906 年 4 月）、OpenSFHistory、美国国会图书馆和 David Rumsey 地图收藏里的历史照片，以及 USGS 地形数据，每栋楼都要标注轮廓、高度、外立面材质、住户以及每条信息的出处和置信度。整个场景全部用 Blender Python 生成，不下载任何现成模型、贴图或 HDRI，还要写出可复用的生成器（维多利亚式商业立面、孟莎屋顶、飘窗、遮阳篷、手绘招牌、煤气与电力路灯、缆车、马车、早期汽车），最后拼出一条能追溯到史料的街道，并生成一段 10 秒视频。他说：“I've been on a Blender kick with Opus 5.5. Its better 3D modeling and vision mean you can build an entire world from a single prompt.”（最近迷上了用 Opus 5.5 做 Blender。它更强的 3D 建模和视觉能力意味着一个 prompt 就能建出一整个世界。）

🔗 https://x.com/alexalbert__/status/2102466524934271381 · https://x.com/alexalbert__/status/2102466523164274839
