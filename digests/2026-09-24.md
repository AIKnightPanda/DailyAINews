### Vercel CEO Guillermo Rauch：拆解 agent 三大件——大脑、双手、文件，发布配套存储组件 Drives

Guillermo Rauch，Vercel CEO，把当下能打的 agent（Muse、Instinct、OpenClaw、Claude Code）拆成三个组件：大脑（模型、执行逻辑的 harness）、双手（工具、电脑、浏览器）、文件（记忆、skills、代码仓库）。他说最简单的做法是把这三者塞进一台常驻的 Mac Mini，用 caffeinate 保持常开、本地装好 CLI 和各种 App；但如果想在云上高性价比地跑 agent，就必须把这些部分拆开：大脑跑在 Fluid Compute 上，靠 Workflow 把事件日志做成持久化，扛得住重启、发布和崩溃；双手交给 Browserbase、Kernel 这类浏览器集群，或者 Sandbox 这样的云电脑，乃至更轻量的 just-bash；而此前一直缺的是把存储也拆解出来的办法——比如想每晚跑一次"记忆整理"的定时任务（他称之为 agent 在"做梦"），需要能直接读写文件，而不必把整台 agent 电脑"开机"。为此 Vercel 推出了配套产品 Drives，相当于给此前发布的 Sandbox 配上一块可以随时挂载的"外接硬盘"。他说：「把 agent 拆成这些独立部件，不仅能大幅优化成本，还能大幅提升安全性和可审计性。」（原文："breaking apart the agent into these independent parts not only optimizes costs in a big way, it also massively improves security and auditability."）

他还提到一个自己搞的小测试 ShellPerfBench：他对新开 shell 会话的启动耗时特别较真，而 Opus 5.5 找出了不少其他模型都漏掉的优化点。他调侃道：「你每次开一个新终端，可能都在悄悄地遭罪。」（原文："anytime you open a new terminal, you might be silently suffering."）他建议大家让自己的 agent 去优化 `.zshrc` 之类的配置文件。

### Anthropic Boris Cherny：用 Opus 5.5 对 Claude Agent SDK 做形式化验证，抓出人工很难发现的并发 bug

Boris Cherny，Anthropic Claude Code 团队成员，展示了用 Opus 5.5 做形式化验证的具体流程：先给容易出竞态或者状态机复杂的代码建模，再在模型里找反例（也就是疑似 bug），然后复现，最后回到代码里修掉。他强调现在还不是把整个代码仓库都做了形式化验证，而是把最"毛"的那些部分单独建模、找反例、修复。他说：「还不是说整个代码库都被形式化验证了（还没到那一步！），更准确地说是把代码里最棘手的那些部分建了模，检查反例，然后修掉。」（原文："It's not that the whole codebase is formally verified (yet!..), more that the hairiest parts of the code are modeled, checked for counter-examples, and fixed."）

他还提到，如果最近觉得 claude.ai 和 Desktop 客户端明显变快了，原因就在这里——团队专门写了一篇博客讲这几周是怎么做到的，里面有不少给做性能优化的工程师看的实用技巧和经验。

### Meta AI 高级总监 Madhu Guru：个人 agent 的潜在需求被严重低估，反驳 Ben Thompson

Madhu Guru，Meta AI 高级总监，此前在 Google 主导过 Gemini、Veo 和 Nano Banana，公开反驳 Ben Thompson 的一个论点：消费者对"把事情做完"这件事不是只有一种关系。他说自己在 Google 和 Meta 做了多年消费级和中小企业产品，深有体会——逛衣服可能是娱乐，但找屋顶维修工对大多数人来说是折磨。哪怕是购物，有时候你想逛一个小时，有时候你只想要东西立刻送到。他把 Thompson 的论调类比成 2000 年代初的老话："为什么要网上买衣服？我得试穿。""为什么要花 500 美元网购电视？我得去 Circuit City 门店看看。"他举了个具体例子说明摩擦有多大：今天找一个屋顶维修工，要搜索、读十条评论、电话来回、协调保险、约检查、要报价、避开隐藏费用、看过往作品，才能下单排期。他的结论是：「能替消费者消除这些摩擦的 agent，其潜在需求是巨大的。」（原文："The latent demand for agents that remove this friction for consumers is immense."）

🔗 https://x.com/realmadhuguru/status/2102777931764498536

### 产品设计师 Ryo Lu：警惕"无限产出"式 AI，真正的前沿是懂得克制

Ryo Lu，先后主导过 Cursor、Notion、Stripe 的产品设计，如今在做自己的创业项目，发了一段少见的长文反思 AI 和"效率崇拜"。他说效率、生产力、速度这些词被当成信仰在供奉——出货更快、合并更多、管理更多 agent、压缩每一个循环、消灭每一次停顿、把每一个小时都变成产出；但如果没有时间深想，这种无止境的产出到底图什么？他说 AI 本该是一块新画布，让更多人触碰到自己想象力的形状，但现实中它正在变成"注水内容工厂"——更多内容、更多转化漏斗、更多工单、更多假装有价值的假工作。他的原话是：「危险不在于 AI 让我们变懒，危险在于 AI 让我们无休止地忙碌。」（原文："the danger is not that ai makes us lazy... the danger is that ai makes us endlessly busy."）他说也许真正的前沿不是更快，而是分寸感：知道什么不该做、知道什么时候该停、知道什么时候最有生产力的事其实是睡觉、读历史、给朋友打电话，或者不追踪任何数据地散个步。
