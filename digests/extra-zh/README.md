# 补充源的筛选与译文缓存

Haiku 在预处理这一步（见 [scripts/routine.md](../../scripts/routine.md) 第 2 步）
把补充源条目筛一遍、译一遍，一期一个 `<期号>.json`：

```json
{
  "drop": [29, 34, 52],
  "sections": { "AI Twitter Recap": "X / Twitter 汇总" },
  "1": ["Harness design is b", "中文标题", "中文背景说明"],
  "2": ["Qwen3-Max-Thinking", "中文标题"]
}
```

- **`drop`** —— 与 AI 无关的条目编号（聚合源里常混进纯生物医药、军事、生活类内容）。
  这些条目不进「延伸阅读」
- **`sections`** —— 板块 / 子版块 / 主题的译名。查不到的用原文
- **数字键** —— 逐条译文。键是 `extract.js` 给的编号，即
  `digests/raw/<期号>.json` 里 `extra.items` 的下标 +1

数字键的值是数组，元素依次为：

1. **英文原标题的开头 18 个字符**，原样照抄，用来做编号对齐校验
2. 中文标题
3. 中文背景说明（可选）—— AINews / The Rundown AI 在版面上只显示标题，不必译背景

**Haiku 只看得到编号和英文标题，看不到 URL** —— `link-digest.js` 按编号把译文和
URL 配回去。所以模型没有能力编造链接。

## 为什么要第一个元素

编号错位是这套设计唯一的真实风险：一旦错位，中文标题会静默地挂到错误的链接上。
所以 `link-digest.js` 会拿第一个元素和英文原标题比对，对不上就**整条退回英文**
并计数告警，绝不把可疑译名配上链接。

缺这个文件、缺某个编号、或文件本身坏了，对应条目一律退回英文原标题，不影响出稿。
（只有一个字符串的老格式仍然兼容，按「中文标题、不校验」处理。）
